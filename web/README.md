# משמרים v2 — אב־טיפוס: מסך הבית של החניך

> **מה זה.** מסך הבית של החניך, בנוי מחדש כאתר רגיל (React) במקום Streamlit:
> נפתח מיד, לא «נרדם», לחיצה מגיבה בתוך פריים, מותאם לטלפון ואפשר להוסיף אותו
> למסך הבית כמו אפליקציה. על **אותו Supabase**, בלי העברת נתונים: החניך רואה את
> המשמרים והמשימות שלו, ובתיק המשמר (`#/m/N`) עובד על לוח המשימות — ✓, הוספה,
> עריכה ומחיקה — ובונה את מבנה הערב: נושא, מקטעים, מרצים ומועמדים, פאנל וחבורות.
> הלוגיסטיקה עוד לקריאה בלבד. המדריך יכול לראות את המסך ואת התיק של כל חניך.
> האפליקציה ב-Streamlit ממשיכה לעבוד כרגיל, על אותם נתונים.
>
> **איפה אנחנו:** שלב 1 (מסך הבית) הוקם ונוסה עם חניכים, שביקשו את כל המערכת כאן.
> שלב 2 מעביר אותה חלק אחר חלק: **2א תיק המשמר** → **2ב עריכת מבנה הערב (כאן)** →
> 2ג לוגיסטיקה, העלאות, משוב ותקציב → 2ד מאגר וחיפוש מרצים → 2ה לוח הבקרה של המדריך.
> מה שעוד לא עבר — עורכים באפליקציה הנוכחית, והמסך החדש אומר את זה במקום.

## הקמה — צעד אחר צעד (פעם אחת, כ-40 דקות)

**לפני שמתחילים:**
- **הכל חינם** — GitHub, Supabase ו-Google; אין כרטיס אשראי באף שלב.
- **כתובת הפרויקט** של Supabase נמצאת ב-Streamlit Cloud → האפליקציה → ⋮ →
  **Settings** → **Secrets**, בשורה `SUPABASE_URL`.
- **המסכים של השירותים באנגלית**, ולכן שמות הכפתורים כתובים כאן באנגלית —
  בדיוק כמו שהם מופיעים.

| שירות | מה הוא עושה |
|---|---|
| **Supabase** | המסד הקיים. פותחים בו שלוש «דלתות» קטנות ומדליקים כניסה עם Google. |
| **GitHub Pages** | שירות האתרים החינמי של GitHub — אותו שירות שכבר מגיש את דפי השבת. ריפו קטן, `mishmar`, בונה ומפרסם את האתר מהקוד שכאן. |
| **Google** | הכניסה. פרויקט חדש ב-Google Cloud ו«מפתח כניסה» (OAuth client) — האפליקציה הנוכחית נכנסת בשם בלבד, ולכן אין ממה להעתיק. |

בסוף שלב ב מצב ההדגמה כבר עובד; אחרי שלב ג עובדת גם הכניסה האמיתית; בשלב ד משייכים
כתובות, המדריך בודק את המסכים, ורק אז החניכים מקבלים קישור.

### שלב א — Supabase: לפתוח את הדלתות (3 דקות)

1. לפתוח את
   [`web/supabase/v2.sql`](https://github.com/urishav464/Ein-Prat-work/blob/claude/mishmer-generator-setup-h5gxqx/web/supabase/v2.sql)
   ב-GitHub ולהעתיק את כולו בכפתור **Copy raw file** (שני ריבועים, מעל הקובץ).
2. https://supabase.com/dashboard → הפרויקט של המשמרים.
3. בתפריט הצד: **SQL Editor** → **New query** (או ה-**+**).
4. להדביק וללחוץ **Run** (או Ctrl+Enter).
5. אמור להופיע **Success. No rows returned**. זהו.

בטוח להריץ שוב — וצריך להריץ שוב בכל פעם שהקובץ משתנה. הוא יוצר את «הדלתות» של
האתר: מסך הבית, תיק המשמר, ✓ והוספה/עריכה/מחיקה של משימות, בניית מבנה הערב, ולמדריך —
לראות את המסכים של החניכים. הוא לא משנה אף טבלה ולא נוגע באפליקציה הנוכחית.

> **אחרי ההרצה, ב-Security Advisor של Supabase תופיע אזהרה לכל דלת** (16 כרגע) —
> «Signed-In Users Can Execute SECURITY DEFINER Function». זה צפוי: התפקיד של הדלתות הוא
> בדיוק שמשתמש מחובר יפעיל אותן. הבודק קורא רק את ההגדרה של פונקציה, לא את מה שבתוכה,
> ולכן לא רואה שכל דלת בודקת מי מתקשר ומרשה רק את מה שמותר לו (`test_v2.py` מוכיח את
> זה). **לא ללחוץ שם על Revoke** — זה סוגר את הדלתות. ה-«Info» על טבלאות עם RLS בלי
> כללים הוא ההגנה הקיימת של האפליקציה, וגם עליו אין מה לעשות.

### שלב ב — GitHub Pages: האתר עצמו (5 דקות)

האתר מתפרסם בכתובת **https://urishav464.github.io/mishmar/**. הקוד נשאר כאן, ב-`web/`;
ריפו קטן ונפרד, [`urishav464/mishmar`](https://github.com/urishav464/mishmar), רק בונה
ומפרסם אותו (`.github/workflows/deploy.yml` שם). ריפו נפרד, כי לכל ריפו ב-GitHub יש
אתר אחד, ושל הריפו הזה כבר תפוס בדפי השבת.

**קודם מכינים שני ערכים:**
- **כתובת הפרויקט** — ב-Streamlit Secrets, השורה `SUPABASE_URL = "https://….supabase.co"`:
  מה שבתוך המירכאות. (גם מירכאות או רווח שנשארו בטעות בסדר — האתר מנקה אותם.)
- **המפתח הציבורי** — ב-Supabase: ⚙️ **Project Settings** (בתחתית תפריט הצד) →
  **API Keys** → ה-**Publishable key** (מתחיל ב-`sb_publishable_`). אם אין כזה:
  הלשונית **Legacy API Keys** → המפתח שכתוב לידו `anon` `public`.

> ⚠️ **לא** את `SUPABASE_KEY` שב-Streamlit Secrets, ולא אף מפתח שכתוב לידו `secret`
> או `service_role` — הם פותחים הכל, והאתר שולח את הערכים האלה לכל דפדפן. מפתח כזה
> גם לא יעבור: הבנייה עצמה נכשלת עליו (`vite.config.ts`) ולא מפרסמת כלום. המפתח
> הציבורי בנוי להיות גלוי: המסד לא נותן לו כלום (ראו «מה גלוי ומה לא»). ולא בקובץ
> `.env` בריפו — רק בהגדרות של GitHub.

**ואז, בריפו `mishmar`:**

1. **ליצור אותו** (פעם אחת): https://github.com/new → **Repository name** `mishmar` →
   **Public** → לסמן **Add a README file** → **Create repository**.
2. **להדליק את האתר:** **Settings** → **Pages** → **Build and deployment** → **Source**:
   **GitHub Actions**.
3. **שני הערכים:** **Settings** → **Secrets and variables** → **Actions** → הלשונית
   **Variables** → **New repository variable**, פעמיים:

   | Name | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | כתובת הפרויקט |
   | `VITE_SUPABASE_ANON_KEY` | המפתח הציבורי |

4. **תהליך הפרסום** נכנס לריפו פעם אחת (`deploy.yml`). מאז הוא בודק כל שעה אם `web/`
   השתנה ובונה רק אם כן; **Actions** → **Publish the site** → **Run workflow** בונה
   מיד. אחרי כל שינוי ב-`web/` מפעילים אותו, כדי לא לחכות לבדיקה הבאה.
5. **בדיקה ראשונה:** בטלפון, `https://urishav464.github.io/mishmar/?demo` → מסך הבית עם
   פס צהוב «מצב הדגמה»: נתוני בדיקה מהמערכת, **השמות הוחלפו** («חניך/ה לדוגמה»,
   «שותף/ה 1»…), ו-✓ מסמן ומבטל מיד בלי לשמור בשום מקום. בלי `?demo` מופיע הכפתור
   «כניסה עם Google» — הוא יעבוד אחרי שלב ג.

> **למה לא Cloudflare:** האתר נבנה ועלה שם בהצלחה (`web/wrangler.jsonc` עדיין מגדיר
> אותו), אבל הכתובת `mishmar-ein-prat.urishav464.workers.dev` נשארה
> `DNS_PROBE_FINISHED_NXDOMAIN` גם אחרי שעה — כמו בדיווחים רבים בפורום של Cloudflare
> בספטמבר–אוקטובר 2026 על כתובות `workers.dev` / `pages.dev` חדשות. אם היא תתחיל לעבוד,
> זה לא מזיק; אפשר גם למחוק את הפרויקט שם.

### שלב ג — כניסה עם Google (15 דקות)

בכל מקום שכתוב כאן `<הפרויקט>.supabase.co` — זו כתובת הפרויקט משלב ב (במשמרים:
`bzrqhgbqkmcfsremxdlf.supabase.co`). היא לא סוד: היא ממילא בתוך האתר.

**א. פרויקט ומסך כניסה ב-Google Cloud**
1. https://console.cloud.google.com/projectcreate → **Project name** `mishmar-ein-prat` →
   **Create**. (בפעם הראשונה ב-Google Cloud: לבחור מדינה ולאשר את התנאים; הצעה
   ל«ניסיון חינם» או לכרטיס אשראי — לא צריך.) בסרגל העליון לוודא שהפרויקט החדש נבחר.
2. https://console.cloud.google.com/auth/overview → **Get started**:
   **App name** `משמרים עין פרת` · **User support email** — הכתובת של המדריך → **Audience**:
   **External** → **Contact information** — שוב אותה כתובת → לסמן את ההסכמה → **Create**.
3. **Branding** (https://console.cloud.google.com/auth/branding):
   - **Application home page** ← `https://urishav464.github.io/mishmar/`
   - **Application privacy policy link** ← `https://urishav464.github.io/mishmar/privacy.html`
     (הדף הזה הוא `web/public/privacy.html`; Google מקשר אליו ממסך הכניסה)
   - **Authorized domains** ← `urishav464.github.io` ו-`<הפרויקט>.supabase.co`
   - **לא להעלות לוגו** — לוגו מחייב בדיקה של Google שלוקחת ימים. → **Save**
4. **Audience** → **Publish app** → **Confirm** → אמור להופיע **In production**.
   בלי סעיף 3 הכפתור אפור: Google דורש דף בית ומדיניות פרטיות לפני שאפליקציה יוצאת
   ממצב בדיקה (שבו רק מי שנרשם ידנית יכול להיכנס). האתר מבקש מ-Google רק שם ומייל,
   ולכן אין צורך בבדיקה של Google.

**ב. מפתח הכניסה — Google ו-Supabase יחד**

Google מציג את הסוד של המפתח רק פעם אחת, ברגע שהוא נוצר — לכן קודם פותחים את Supabase:

1. **Supabase** → **Authentication** → **Sign In / Providers** → **Google** → להדליק
   **Enable Sign in with Google**, ולהשאיר את החלון פתוח.
2. **Google:** https://console.cloud.google.com/auth/clients/create → **Application type**:
   **Web application** → **Name** `Supabase` → **Authorized redirect URIs** → **Add URI** ←
   `https://<הפרויקט>.supabase.co/auth/v1/callback` (זהה ל-**Callback URL** שמופיע בחלון
   של Supabase) → **Create**.
3. בחלון שנפתח ב-Google: להעתיק את **Client ID** לשדה **Client IDs** ב-Supabase, ואת
   **Client secret** לשדה **Client Secret (for OAuth)** → **Save** ב-Supabase.
   הסוד הולך רק לשם. (נסגר החלון לפני שהועתק? בדף של המפתח ב-Google → **Add secret**.)

**ג. לאן חוזרים אחרי הכניסה**
1. **Supabase** → **Authentication** → **URL Configuration**:
   - **Site URL** ← `https://urishav464.github.io/mishmar/` → **Save changes**
   - **Redirect URLs** → **Add URL** ← `https://urishav464.github.io/mishmar/**` → **Save URLs**
2. **בדיקה:** בטלפון, הכתובת בלי `?demo` → **כניסה עם Google**. Google עשוי לכתוב
   «להמשיך אל `<הפרויקט>.supabase.co`» — זה תקין. **מופיע «לא משויכת לאף חניך»? מצוין**:
   הכניסה עובדת מקצה לקצה, ורק עוד לא שויכה כתובת (שלב ד).
3. (רשות) **Sign In / Providers** → **Email** → לכבות. לא משפיע על האפליקציה
   הנוכחית — היא לא משתמשת בכניסה של Supabase — והדלתות ממילא מסרבות לכל מי
   שלא נכנס דרך Google.

### שלב ד — לשייך, לבדוק כמדריך, לנסות עם חניכים

1. **לשייך כתובות.** באפליקציה הנוכחית → **לוח הבקרה** → **«🔗 שיוך חשבונות»**:
   - ליד כל חניך — כתובת ה-Gmail **שאיתה הוא נכנס ל-Google בטלפון**;
   - בשורה **«Uri (מדריך)»** — הכתובת של המדריך עצמו;
   - **«שמור שיוכים»**. (החלונית או השורה לא מופיעות? https://share.streamlit.io → ⋮ ליד
     האפליקציה → **Reboot app**, ואז לרענן.)
2. **לבדוק כמדריך, לפני שהקישור נשלח.** להיכנס לאתר עם הכתובת של המדריך → רשימת
   החניכים → לחיצה על שם פותחת את המסך של אותו חניך **בדיוק כפי שהוא רואה אותו**, עם פס
   «מצב מדריך». זו צפייה בלבד: ✓ משתנה על המסך ולא נשמר, ו-«לרשימת החניכים» חוזר לרשימה.
   מה שצריך תיקון — מתקנים באפליקציה הנוכחית, והאתר מראה את זה בכניסה הבאה.
3. **הניסיון עצמו:** חניך או שניים פותחים את הכתובת בטלפון שלהם ונכנסים עם החשבון
   שהכתובת שלו שויכה. הם רואים את המשמרים והמשימות האמיתיים שלהם. ✓ נשמר מיד;
   באפליקציה הנוכחית הסימון מופיע תוך רבע שעה לכל היותר (היא «זוכרת» נתונים כדי להיות
   מהירה).
4. **על מה להסתכל:** כמה מהר זה נפתח, איך זה מרגיש בטלפון, האם זה ברור יותר
   מהאפליקציה הנוכחית, והוספה למסך הבית (באייפון: שיתוף → «הוסף למסך הבית»;
   באנדרואיד: ⋮ → «הוסף למסך הבית»).
5. ההחלטה: ממשיכים לבנייה המלאה, או נשארים עם Streamlit.

### אם משהו נתקע

| מה רואים | מה עושים |
|---|---|
| «404» או «There isn't a GitHub Pages site here» | הפרסום עוד לא רץ בהצלחה. בריפו `mishmar` → **Actions** → **Publish the site**: אם יש ✗ אדום — לבדוק ש-**Source** ב-Pages הוא **GitHub Actions**, ואז **Run workflow** |
| גם בלי `?demo` מופיע הפס הצהוב | שני הערכים לא הגיעו לבנייה (שם לא מדויק, או שהוגדרו תחת Secrets במקום Variables). מתקנים ב-**Settings → Secrets and variables → Actions → Variables** של `mishmar`, ואז **Run workflow** |
| מסך «כתובת הפרויקט בהגדרות האתר לא תקינה» / «המפתח לא מזוהה» | הערך באחד המשתנים לא נכון — המסך עצמו אומר איזה ואיך לתקן; אחרי התיקון **Run workflow** |
| הפרסום נכשל עם «SECRET Supabase key» | הוזן המפתח הסודי. להחליף במפתח הציבורי ולהריץ שוב — ולהחליף ב-Supabase את המפתח הסודי עצמו, כי הוא הודבק במקום שלא נועד לו |
| **Publish app** אפור, עם הסבר על homepage / privacy policy | שלב ג-א-3: דף הבית וקישור מדיניות הפרטיות ב-**Branding**, ואז **Save** |
| Google מסרב לשמור את כתובת החזרה ומבקש *authorized domain* | **Branding → Authorized domains → Add domain** ← `<הפרויקט>.supabase.co` (לא `supabase.co` לבד — Google לא מקבל אותו), **Save**, ושוב שלב ג-ב-2 |
| Google כותב `redirect_uri_mismatch` | הכתובת ב-**Authorized redirect URIs** שונה מה-**Callback URL** של Supabase — לבדוק שאין רווח או `/` מיותר. לפעמים לוקח ל-Google כמה דקות להתעדכן |
| Google כותב «Access blocked» / «has not completed the Google verification process» | האפליקציה עוד ב-**Testing**: שלב ג-א-4 (**Publish app**) |
| חניך רואה «לא משויך» | המסך מציג את הכתובת שאיתה נכנס — להשוות למה שרשום ב-«שיוך חשבונות» ולתקן |
| המדריך רואה «לא משויך» | הכתובת שלו לא בשורה «Uri (מדריך)», או ש-`v2.sql` לא הורץ מאז שנוספה דלת המדריך — שלב א שוב |
| «משהו השתבש» | שלב א לא רץ, או רץ על פרויקט אחר — להריץ אותו שוב |

## איך זה נבדק

```bash
python3 scripts/harness/db.py up
python3 web/supabase/test_v2.py            # 54 בדיקות אבטחה מול PostgreSQL 16 מקומי
python3 web/supabase/test_v2_structure.py  # מבנה הערב: האתר מול האפליקציה, צעד אחר צעד
python3 web/check_ui.py                     # 115 בדיקות בכרום, בטלפון (390) ובמחשב (1500)
```

(אותה סביבת Python של ה-harness — `psycopg2` ו-Playwright — ו-`npm install` שבוצע ב-`web/`.)

- **המסד:** עותק של ה-fixture מקבל קודם את ההרשאות ש-Supabase נותן מעצמו לכל
  פרויקט חדש (הכל פתוח ל-`anon` ול-`authenticated`), ורק אז רצים עליו
  `supabase_schema.sql` והקובץ של v2 (פעמיים). נבדק: `anon` לא יכול אפילו לקרוא
  לפונקציות; בלי התחברות / כניסה במייל / כתובת לא משויכת — אין נתונים ואין שינוי;
  חניך משויך מקבל רק את המשמרים שלו, לא משימה ששייכת לשותף בלבד, ואף מפתח
  `phone`/`email`/`contact`/`details`; ✓ שלו משנה רק את הסטטוס ואת זמן העדכון, ונחסם
  — בלי לשנות דבר — על משימה של השותף, של משמר אחר, על משימה שלא קיימת ועל סטטוס
  לא חוקי. **המדריך** מקבל רק שמות ומספרים של החניכים; המסך שהוא רואה לכל חניך זהה
  לתשובה שהחניך עצמו מקבל; חניך, כתובת לא משויכת ו-`anon` נחסמים בדלת שלו; והסימון
  נחסם לו בלי לשנות דבר. כתובת שרשומה גם על חניך וגם על המדריך — החניך קודם. בקטלוג
  כולו נשארות שלוש הרשאות בלבד לתפקידים הציבוריים — `EXECUTE` על שלוש הדלתות,
  ל-`authenticated` — ואין שום גישה לסכמה `v2_private` שמאחוריהן. בדיקת ביקורת: בלי
  ה-REVOKE-ים אותה שאילתה מוצאת עשרות הרשאות פתוחות — כולל `anon` שמסמן משימות.
  **תיק המשמר:** הזוג מקבל רק ערב שלו (כל המשימות, המקטעים והאנשים עליהם); טלפון
  מופיע **רק** ברשימות האנשים של המקטעים, ומייל או פרטי קשר — בשום מקום; הוספה כותבת
  בדיוק את הקטגוריה והתאריך ש-`dm.add_task` היה כותב; עריכה משנה רק כותרת, פרטים,
  תאריך ומקטע (ומקטע של ערב אחר נדחה); ערב אחר, המדריך ו-`anon` נדחים בכל דלת כתיבה
  בלי לשנות דבר. **התאומים:** הסיווג והתאריך המומלץ קיימים גם ב-SQL — כל מילת מפתח
  וכל טקסט משימה מסווגים זהה בשני המקומות, וכל קטגוריה × תאריך מקבלים אותו תאריך.
  **מבנה הערב:** תשע דלתות הכתיבה נחסמות ל-`anon`, בלי התחברות, בכניסה במייל, לכתובת
  לא משויכת, בערב אחר, על מקטע או אדם שלא קיימים, ולמדריך — ובשום סירוב שום דבר לא
  משתנה; קלט לא תקין (נושא ריק, 4 דקות, קישור `javascript:`, חלל חמישי, סטטוס ממוצא)
  נדחה בשמו; ותשובה מוצלחת היא בדיוק `v2_workfile` טרי. **מה שהן כותבות** נבדק ב-
  `test_v2_structure.py`: שני עותקים של ה-fixture — על אחד `data_manager` (הקולבקים של
  Streamlit, ואחריהם הסנכרון), על השני הדלתות בתור החניך — ואחרי **כל** צעד משווים את
  הערב, את מאגר המרצים ואת יומן הפניות: תרחיש קבוע שעובר בכל מסלול של כל דלת, מצבים
  ישנים שהסנכרון צריך לסדר, והליכות אקראיות (1,500 צעדים בחמש הרצות — זהים). שנים-עשר
  באגים שנשתלו בכוונה בעותק של `v2.sql` — כל אחד נתפס.
- **הממשק:** כל בנייה מוגשת מתת-נתיב (`/mishmar/`, כמו ב-GitHub Pages) כדי להוכיח שכל
  קישור, אייקון וה-manifest יחסיים — הדגמה, ובנייה שמכוונת ל-Supabase מדומה שהבדיקה
  עצמה עונה לבקשות שלו — כך שמסלול ההתחברות רץ באמת בלי חשבון: הכפתור מבקש
  `provider=google` עם PKCE, דף הפרטיות מקושר ולא טוען שום דבר מבחוץ, סשן שמור שולח
  **קריאה אחת** עם הטוקן של המשתמש, ✓ מצויר מחדש תוך פריים ואז יוצאת **שמירה אחת** של
  אותה משימה, ביטול שומר «בתהליך» (כמו «↩ החזר לתהליך» באפליקציה הנוכחית), שמירה
  שנכשלה מחזירה את המשימה ואומרת זאת, משימות באיחור מקופלות שורה לכל משמר לפי תאריך,
  **המדריך** רואה רשימה, בחירה שולחת קריאה אחת למסך של אותו חניך ו-✓ שם לא שולח שום
  שמירה, והמסכים «לא משויך» (עם הקישור להדגמה) / «רק Google» / «שגיאה» / «התנתקות».
  **תיק המשמר:** קריאה **אחת**, וכל ✓ / הוספה / עריכה / מחיקה — קריאה אחת שאומרת בדיוק
  מה; טלפון כקישור חיוג, וכתובת `javascript:` אף פעם לא הופכת לקישור; למדריך — בלי שום
  כפתור כתיבה ובלי שום קריאת כתיבה. **מבנה הערב:** כל פקד — מועמד, סטטוס, טלפון,
  סגירה, החלפה, הסרה, עורך המקטע, הפסקה, חלל, מעביר, נושא, שלד — שולח קריאה אחת עם
  בדיוק מה שהוא אומר, והמסך מצויר מהתשובה; סירוב ושגיאה נאמרים בלי לשנות את המסך;
  למדריך אין אף פקד עריכה; ובהדגמה השינוי מופיע על המסך ושום קריאה לא יוצאת.
  ✓ בהדגמה מצויר מחדש תוך ~9ms (ב-Streamlit: 400–650ms).

## מה עוד לא כאן — בכוונה

לוגיסטיקה, העלאות (גם דף מקורות כקובץ — בינתיים קישור), משוב ותקציב (2ג), מאגר וחיפוש
מרצים (2ד), שעת הפתיחה של ערב ולוח הבקרה של המדריך (2ה), וטבלאות ארגון/שנה למכינות
נוספות. עד אז — באפליקציה הנוכחית.
