# משמרים v2 — אב־טיפוס: מסך הבית של החניך

> **מה זה.** מסך הבית של החניך, בנוי מחדש כאתר רגיל (React) במקום Streamlit:
> נפתח מיד, לא «נרדם», לחיצה מגיבה בתוך פריים, מותאם לטלפון ואפשר להוסיף אותו
> למסך הבית כמו אפליקציה. על **אותו Supabase**, בלי העברת נתונים: החניך רואה את
> המשמרים והמשימות שלו ומסמן ✓. האפליקציה ב-Streamlit ממשיכה לעבוד כרגיל; שום דבר
> כאן לא נוגע בה.
>
> **זה שלב 1 מתוך ארבעה — מסך הבית האמיתי.** ההדגמה עברה את השער; שלב 2 (שאר
> המסכים) מחכה לניסיון של שלב 1 עם חניכים אמיתיים.

## הקמה — צעד אחר צעד (פעם אחת, כ-25 דקות)

**לפני שמתחילים:**
- **הכל חינם** — Cloudflare, Supabase ו-Google; אין כרטיס אשראי באף שלב.
- **כמעט כל ערך להעתקה כבר נמצא במקום אחד:** Streamlit Cloud → האפליקציה → ⋮ →
  **Settings** → **Secrets**. כדאי לפתוח אותו בלשונית נפרדת.
- **המסכים של השירותים באנגלית**, ולכן שמות הכפתורים כתובים כאן באנגלית —
  בדיוק כמו שהם מופיעים.

| שירות | מה הוא עושה |
|---|---|
| **Supabase** | המסד הקיים. פותחים בו «דלת» אחת קטנה ומדליקים כניסה עם Google. |
| **Cloudflare** | שירות חינמי שמארח את האתר עצמו. כל push לברנץ׳ בונה אותו מחדש לבד, כמו Streamlit היום. |
| **Google** | הכניסה. אותו OAuth client שכבר משמש את Streamlit — מוסיפים לו כתובת אחת. |

בסוף שלב ב מצב ההדגמה כבר עובד; אחרי שלב ג עובדת גם הכניסה האמיתית.

### שלב א — Supabase: לפתוח את הדלת (3 דקות)

1. לפתוח את
   [`web/supabase/v2.sql`](https://github.com/urishav464/Ein-Prat-work/blob/claude/mishmer-generator-setup-h5gxqx/web/supabase/v2.sql)
   ב-GitHub ולהעתיק את כולו בכפתור **Copy raw file** (שני ריבועים, מעל הקובץ).
2. https://supabase.com/dashboard → הפרויקט של המשמרים.
3. בתפריט הצד: **SQL Editor** → **New query** (או ה-**+**).
4. להדביק וללחוץ **Run** (או Ctrl+Enter).
5. אמור להופיע **Success. No rows returned**. זהו.

בטוח להריץ שוב — וצריך להריץ שוב בכל פעם שהקובץ משתנה. הוא יוצר את שתי «הדלתות»
של האתר: לקרוא את מסך הבית, ולסמן ✓. הוא לא משנה אף טבלה ולא נוגע באפליקציה
הנוכחית.

> **אחרי ההרצה, ב-Security Advisor של Supabase יופיעו שתי אזהרות** «Signed-In Users
> Can Execute SECURITY DEFINER Function» — אחת לכל דלת. זה צפוי: התפקיד של הדלתות הוא
> בדיוק שמשתמש מחובר יפעיל אותן. הבודק קורא רק את ההגדרה של פונקציה, לא את מה שבתוכה,
> ולכן לא רואה שכל דלת בודקת מי מתקשר ומרשה רק את המשמרים שלו (`test_v2.py` מוכיח את
> זה). **לא ללחוץ שם על Revoke** — זה סוגר את הדלתות. ה-«Info» על טבלאות עם RLS בלי
> כללים הוא ההגנה הקיימת של האפליקציה, וגם עליו אין מה לעשות.

### שלב ב — Cloudflare: האתר עצמו (10 דקות)

**קודם מכינים שני ערכים:**
- **כתובת הפרויקט** — ב-Streamlit Secrets, השורה `SUPABASE_URL = "https://….supabase.co"`:
  מה שבתוך המירכאות. (גם מירכאות או רווח שנשארו בטעות בסדר — האתר מנקה אותם.)
- **המפתח הציבורי** — ב-Supabase: ⚙️ **Project Settings** (בתחתית תפריט הצד) →
  **API Keys** → ה-**Publishable key** (מתחיל ב-`sb_publishable_`). אם אין כזה:
  הלשונית **Legacy API Keys** → המפתח שכתוב לידו `anon` `public`.

> ⚠️ **לא** את `SUPABASE_KEY` שב-Streamlit Secrets, ולא אף מפתח שכתוב לידו `secret`
> או `service_role` — הם פותחים הכל, והאתר שולח את הערכים האלה לכל דפדפן. מפתח כזה
> גם לא יעבור: הבנייה עצמה נכשלת עליו (`vite.config.ts`) ולא מפרסמת כלום. המפתח
> הציבורי בנוי להיות גלוי: המסד לא נותן לו כלום (ראו «מה גלוי ומה לא»). ולא בקובץ
> `.env` בריפו — רק בהגדרות של Cloudflare.

**ואז:**

1. להירשם בחינם: https://dash.cloudflare.com/sign-up (מייל + סיסמה, ולאשר את המייל).
2. בתפריט הצד: **Workers & Pages** → **Create application** → **Import a repository**
   (Cloudflare מוביל היום ל-Worker — זה בסדר: `web/wrangler.jsonc` מגדיר אותו כאתר
   של קבצים סטטיים, בלי קוד שרת).
3. **Connect GitHub** → כש-GitHub שואל: **Only select repositories** → `Ein-Prat-work`
   → **Install & Authorize** → בחזרה ב-Cloudflare לבחור את `Ein-Prat-work`.
4. במסך **Set up your application** למלא:

   | שדה | מה לכתוב |
   |---|---|
   | Project name | `mishmar-ein-prat` — **בדיוק כך**: זה השם שב-`web/wrangler.jsonc` |
   | Build command | `npm run build` |
   | Deploy command | `npx wrangler deploy` (ברירת המחדל) |
   | Enable Preview builds | **לכבות** — אחרת כל שמירה בענפים אחרים בריפו (למשל השבת) מנסה לבנות כאן, נכשלת ושולחת מייל |
   | Advanced settings → Path | `web` |
   | ענף (אם מופיע) | `claude/mishmer-generator-setup-h5gxqx` |

5. **המשתנים** — אם תחת **Advanced settings** יש מקום למשתנים (Build variables),
   להוסיף שניים שם:

   | Variable name | Value |
   |---|---|
   | `VITE_SUPABASE_URL` | כתובת הפרויקט |
   | `VITE_SUPABASE_ANON_KEY` | המפתח הציבורי |

   אם אין — אחרי הבנייה הראשונה: הפרויקט → **Settings** → **Build** → **Variables and
   secrets** (משתני **הבנייה**, לא «Variables and Secrets» של זמן הריצה), ואז לבנות שוב.
6. **Deploy**, ולחכות 1–3 דקות להצלחה. כתובת האתר: `https://mishmar-ein-prat.<שם-החשבון>.workers.dev`.
7. **בדיקה ראשונה:** בטלפון, הכתובת עם `/?demo` בסוף → מסך הבית עם פס צהוב «מצב
   הדגמה»: נתוני בדיקה מהמערכת, **השמות הוחלפו** («חניך/ה לדוגמה», «שותף/ה 1»…), ו-✓
   מסמן ומבטל מיד בלי לשמור בשום מקום. בלי `?demo` מופיע הכפתור «כניסה עם Google» —
   הוא יעבוד אחרי שלב ג.

   > **כתובת חדשה לגמרי לוקחת זמן.** בפעם הראשונה Cloudflare יוצר גם את
   > `<שם-החשבון>.workers.dev` עצמו, ועד שהכתובת מתפשטת ברשת הטלפון כותב
   > `DNS_PROBE_FINISHED_NXDOMAIN` («This site can't be reached»). לחכות 15–30 דקות;
   > לנסות גם בגלישה סלולרית במקום Wi-Fi, ובמחשב.

### שלב ג — כניסה עם Google (10 דקות)

1. **Supabase** → בתפריט הצד **Authentication** → **Sign In / Providers** → **Google**
   → להדליק **Enable Sign in with Google**.
2. באותו חלון, מתוך Streamlit Secrets (החלק `[auth]`):
   - **Client IDs** ← הערך של `client_id` (נגמר ב-`.apps.googleusercontent.com`)
   - **Client Secret** ← הערך של `client_secret` (מתחיל ב-`GOCSPX-`)

   מעתיקים מ-Streamlit, כי Google כבר לא מציג סוד קיים במסך שלו — רק ברגע שנוצר.
3. באותו חלון: להעתיק את **Callback URL (for OAuth)** (נראה כמו
   `https://xxxx.supabase.co/auth/v1/callback`), ואז **Save**.
4. **Google Cloud:** https://console.cloud.google.com/auth/clients (במסכים ישנים:
   **APIs & Services** → **Credentials**) → למעלה לוודא שנבחר הפרויקט של כניסת
   המשמרים → ללחוץ על ה-client הקיים (ה-ID שלו זהה ל-`client_id`) → תחת
   **Authorized redirect URIs** → **+ Add URI** → להדביק את הכתובת מצעד 3 → **Save**.

   > ⚠️ **להוסיף, לא להחליף.** הכתובת של Streamlit שכבר רשומה שם חייבת להישאר,
   > אחרת הכניסה לאפליקציה הנוכחית תישבר.
5. **Supabase** → **Authentication** → **URL Configuration**:
   - **Site URL** ← כתובת האתר (למשל `https://mishmar-ein-prat.urishav464.workers.dev`) → **Save**
   - **Redirect URLs** → **Add URL** ← אותה כתובת עם `/**` בסוף → **Save**
6. (רשות) **Sign In / Providers** → **Email** → לכבות. לא משפיע על האפליקציה
   הנוכחית — היא לא משתמשת בכניסה של Supabase — והפונקציה ממילא מסרבת לכל מי
   שלא נכנס דרך Google.

### שלב ד — לנסות, ולהחליט

1. בטלפון, כתובת האתר בלי `?demo` → **כניסה עם Google** → לבחור חשבון. Google עשוי
   לכתוב «להמשיך אל xxxx.supabase.co» — זה תקין.
2. **כשנכנסים עם חשבון המדריך, מופיעה ההודעה «לא משויכת לאף חניך» — וזה צפוי.**
   אב־הטיפוס הוא המסך של החניך, והמדריך רשום במסד עם `role = 'instructor'`
   (Streamlit מזהה אותו לפי `admin_emails`). ההודעה אומרת את זה בעצמה ונותנת
   קישור למצב ההדגמה.
3. **הבדיקה האמיתית:** חניך או שניים פותחים את הכתובת בטלפון שלהם ונכנסים עם אותו
   חשבון Google שהם נכנסים איתו היום. הם רואים את המשמרים והמשימות האמיתיים שלהם.
   **שיוך — כמו היום:** האתר קורא את אותה כתובת ששויכה בלוח הבקרה של Streamlit,
   תחת «שיוך חשבונות»; אין מה לשייך מחדש. ✓ נשמר מיד; באפליקציה הנוכחית הסימון
   מופיע תוך רבע שעה לכל היותר (היא «זוכרת» נתונים כדי להיות מהירה).
4. **על מה להסתכל:** כמה מהר זה נפתח, איך זה מרגיש בטלפון, האם זה ברור יותר
   מהאפליקציה הנוכחית, והוספה למסך הבית (באייפון: שיתוף → «הוסף למסך הבית»;
   באנדרואיד: ⋮ → «הוסף למסך הבית»).
5. ההחלטה: ממשיכים לבנייה המלאה, או נשארים עם Streamlit.

### אם משהו נתקע

| מה רואים | מה עושים |
|---|---|
| `DNS_PROBE_FINISHED_NXDOMAIN` / «This site can't be reached» | הכתובת חדשה ועוד לא התפשטה (ראו שלב ב-7) — לחכות 15–30 דקות, ולנסות בגלישה סלולרית ובמחשב. אם רשת ה-Wi-Fi מסוננת, ייתכן שהיא חוסמת כתובות חדשות |
| גם בלי `?demo` מופיע הפס הצהוב | המשתנים לא הגיעו לבנייה (אולי שם לא מדויק, או שהם הוגדרו כמשתני זמן ריצה). מתקנים ב-**Settings → Build → Variables and secrets**, ואז בונים שוב — משתנה נכנס לתוקף רק בבנייה חדשה |
| מסך «כתובת הפרויקט בהגדרות האתר לא תקינה» / «המפתח לא מזוהה» | הערך באחד המשתנים לא נכון — המסך עצמו אומר איזה ואיך לתקן; אחרי התיקון בונים שוב |
| הבנייה ב-Cloudflare נכשלה עם «SECRET Supabase key» | הוזן המפתח הסודי. להחליף במפתח הציבורי ולבנות שוב — ולהחליף ב-Supabase את המפתח הסודי עצמו, כי הוא הודבק במקום שלא נועד לו |
| Google כותב `redirect_uri_mismatch` | הכתובת מצעד ג-3 לא נוספה בדיוק — לבדוק שאין רווח או `/` מיותר. לפעמים לוקח ל-Google כמה דקות להתעדכן |
| Google מסרב לשמור את הכתובת ומבקש *authorized domain* | **Google Auth Platform → Branding → Authorized domains → Add domain** → `supabase.co` → **Save**, ואז שוב צעד ג-4 |
| חניך רואה «לא משויך» | הכתובת שלו לא משויכת — התיקון כמו היום: «שיוך חשבונות» בלוח הבקרה |
| «משהו השתבש» | שלב א לא רץ, או רץ על פרויקט אחר — להריץ אותו שוב |

## מה גלוי ומה לא

| מי | מה הוא מקבל |
|---|---|
| כל אחד, עם המפתח הציבורי | **כלום.** אף טבלה, אף תצוגה, אף פונקציה |
| נכנס עם Google, לא משויך (כולל המדריך) | הודעת «לא משויך» וקישור למצב ההדגמה — בלי שום נתון |
| נכנס עם Google, משויך | שתי פעולות בלבד: לקרוא את המשמרים **שלו**, שמות הזוג והמשימות של המשמרים האלה; ולסמן ✓ במשימה של אחד מהם — לא במשימה ששייכת לשותף בלבד. **אף פעם** לא טלפון, מייל, פרטי קשר או ההערות החופשיות של משימה |
| מי שפותח `?demo` | נתוני בדיקה, השמות הוחלפו |

הטבלאות נשארות נעולות בדיוק כמו היום (RLS בלי מדיניות, אפס הרשאות ל-`anon`
ול-`authenticated`); שתי הפונקציות הן הדלתות היחידות, והן עונות רק לחניך שהכתובת
שלו משויכת.

## איך זה נבדק

```bash
python3 scripts/harness/db.py up
python3 web/supabase/test_v2.py         # 22 בדיקות מול PostgreSQL 16 מקומי
python3 web/check_ui.py                  # 50 בדיקות בכרום, בטלפון (390) ובמחשב (1500)
```

(אותה סביבת Python של ה-harness — `psycopg2` ו-Playwright — ו-`npm install` שבוצע ב-`web/`.)

- **המסד:** עותק של ה-fixture מקבל קודם את ההרשאות ש-Supabase נותן מעצמו לכל
  פרויקט חדש (הכל פתוח ל-`anon` ול-`authenticated`), ורק אז רצים עליו
  `supabase_schema.sql` והקובץ של v2. נבדק: `anon` לא יכול אפילו לקרוא לפונקציות;
  בלי התחברות / כניסה במייל / כתובת לא משויכת — אין נתונים ואין שינוי; חניך משויך
  מקבל רק את המשמרים שלו, לא משימה ששייכת לשותף בלבד, ואף מפתח
  `phone`/`email`/`contact`/`details`; ✓ שלו משנה רק את הסטטוס ואת זמן העדכון, ונחסם
  — בלי לשנות דבר — על משימה של השותף, של משמר אחר, על משימה שלא קיימת ועל סטטוס
  לא חוקי; ובקטלוג כולו נשארות שתי הרשאות בלבד לתפקידים הציבוריים — `EXECUTE` על
  שתי הדלתות, ל-`authenticated` — ואין שום גישה לסכמה `v2_private` שמאחוריהן.
  בדיקת ביקורת: בלי ה-REVOKE-ים אותה שאילתה מוצאת 68 הרשאות פתוחות — כולל `anon`
  שמסמן משימות.
- **הממשק:** שתי בניות, שתיהן מוגשות מתת-נתיב (`/v2/`) כדי להוכיח שכל קישור, אייקון וה-manifest יחסיים — הדגמה, ובנייה שמכוונת ל-Supabase מדומה שהבדיקה עצמה
  עונה לבקשות שלו — כך שמסלול ההתחברות רץ באמת בלי חשבון: הכפתור מבקש
  `provider=google` עם PKCE, סשן שמור שולח **קריאה אחת** עם הטוקן של המשתמש, ✓
  מצויר מחדש תוך פריים ואז יוצאת **שמירה אחת** של אותה משימה, ביטול שומר «בתהליך»
  (כמו «↩ החזר לתהליך» באפליקציה הנוכחית), שמירה שנכשלה מחזירה את המשימה ואומרת
  זאת, משימות באיחור מקופלות שורה לכל משמר לפי תאריך, והמסכים
  «לא משויך» (עם הקישור להדגמה, שנבדק שהוא עובד) / «רק Google» / «שגיאה» / «התנתקות». ✓ בהדגמה מצויר מחדש תוך ~9ms
  (ב-Streamlit: 400–650ms).

## מה עוד לא כאן — בכוונה

לוח הבקרה של המדריך, תיק המשמר, חיפוש מרצים, וטבלאות ארגון/שנה למכינות נוספות —
כל אלה בשלב 2, אחרי הניסיון של שלב 1.

## מבנה

